# Personal Intelligence Agency

Human goal: maintain a small, evidence-bound operating system that converts uncertainty into decisions, actions, and proof for Jordan McCarthy.

This project preserves reusable architecture, prompts, schemas, and provenance. It must never contain private raw inbox/calendar exports, message transcripts, unpublished JM105 data, account balances, health records, or other sensitive source material.

## Constitution

> No intelligence without command. No command without proof. No proof, no claim that the system worked.

The agency exists only where uncertainty blocks a decision. It must not generate analysis as a substitute for scientific work, customer discovery, written commitments, or financial instrumentation.

Collection is allowed only when it names:

1. an active Priority Intelligence Requirement (PIR);
2. the decision supported;
3. the Latest Time Information Is Of Value (LTIOV);
4. the minimum sufficient source set; and
5. the action unlocked if the answer changes.

If one of these is missing, the collection requirement is killed.

## Current command scope

Only two campaigns are peers on the command board:

1. **JM105 to submission** — current stage: `PANEL_AUDIT_QC`.
2. **Money, career, ownership, and commercialization option validation**.

Code/provenance, health/body, and network/relationships are subordinate evidence or operating feeds. They enter command only when they directly affect an active PIR or a pre-registered warning tripwire.

## Source-of-truth architecture

### Tier 1 — Evidence

Append-only and non-interpretive:

- Master Interaction Record;
- Proof Ledger;
- Forecast Ledger and resolved outcomes;
- Wrong Log;
- sent messages, held meetings, commits, saved artifacts, signed documents, and verified source records.

Tier 1 contains no recommendation, motive, relationship score, or inferred state.

### Tier 2 — State

Versioned and written by a designated owner:

- Canonical Current State Ledger;
- Weekly Operating Board;
- Connection Tracking structured CRM;
- Key Assumptions Register;
- Indicators & Warning Matrix;
- OPSEC Critical Information List;
- Zürich Ownership model.

Every Tier-2 change must be traceable to Tier-1 evidence.

### Tier 3 — Judgment

Regenerable and non-authoritative:

- Weekly Estimate;
- Devil's Advocate;
- Network Profiles;
- Weekly Preemption Watch;
- ACH and premortems;
- bounded code/provenance or Swiss-decision analysis.

Tier 3 never becomes Tier-2 state by being repeated. It submits a change request with evidence, an alternative explanation, probability where resolvable, LTIOV, and expiry.

## Writer map

- **Reconcile and Command** is the sole automated writer for the Canonical Ledger, Weekly Operating Board, Forecast/Calibration/Wrong/Proof/Change Queue surfaces, assumptions, warning, OPSEC, and Zürich Ownership registers.
- **Network Evidence** is the sole writer for the Master Interaction Record, Connection Tracking, and Network Profiles.
- **Weekly Preemption Watch**, **Devil's Advocate**, and **Weekly Estimate** are read-only against state and may only file change requests.

Exactly one writer exists per artifact.

## Feedback and calibration

The former 21-point signal score is retired. It produced confidence without demonstrated accuracy.

The system now uses:

- 20–40 timestamped, resolvable probability forecasts;
- immutable original probabilities;
- binary outcomes and Brier scores;
- monthly calibration review as outcomes resolve;
- a Wrong Log for missed forecasts, failed recommendations, stale state, automation bias, and containment changes.

CARVER is permitted only for ranking operational targets or gates. It is not a truth, importance, or confidence score.

## Warning and OPSEC

Indicators must be registered before the event. The current matrix includes tripwires for:

- material JM105 overlap from a named lab or preprint;
- Yves avoidance or explicit refusal;
- accelerated Barral-lab closure timing;
- Pioneer rule changes;
- four customer conversations yielding no costly problem or commitment;
- public disclosure of a Critical Information List item;
- architecture-level failure during JM105 panel audit;
- failure to verify the financial baseline.

The OPSEC Critical Information List protects the exact Mud1/CR/NMD contrast logic, decisive candidate sets, figure-to-claim architecture, old-cell/aging-chip know-how, and unvalidated commercial thesis.

## Operations-led cycle

Use:

`Find → Fix → Finish → Exploit → Analyze → Disseminate`

Every important interaction defines its exploit before it happens: the document, introduction, commitment, disconfirmation, workflow, budget signal, or next gate to obtain. A meeting without an exploit is not a completed operation.

## Recommendation hygiene

- Every recommendation has a hard expiry; default 30 days or the earlier LTIOV.
- Expired recommendations auto-archive unless re-justified by new Tier-1 evidence.
- Downstream artifacts suppress completed upstream milestones.
- A written artifact is required before describing Yves as committed.
- Scheduled customer conversations do not count; only held conversations count.
- No Zürich purchase timeline is valid while net worth, burn, savings, income, deployable capital, and financing constraints remain unverified.

## Current automation core

The architecture is intentionally limited to five active processes:

1. Reconcile and Command.
2. Network Evidence.
3. Weekly Preemption Watch.
4. Devil's Advocate.
5. Weekly Estimate.

Additional desks should be folded into these unless a new PIR and separate authority boundary genuinely require another process.

## Canonicality and privacy rules

- Preserve reusable logic and human-readable architecture.
- Do not commit daily private intelligence products.
- Do not treat repository documentation as proof that an automation delivered its output.
- Do not store credentials, private Drive links containing sensitive content, financial values, message text, or unpublished biological data.
- Mark old prompts `HISTORICAL / SUPERSEDED`; they must not be read as current commands.
- Exact current operational state lives in the private control artifacts, not this README.

## 30-day operational test

By 2026-08-12, the system should have evidence of:

1. a written, decision-grade Yves commitment or a triggered fallback path;
2. four held customer-discovery conversations with exploit artifacts;
3. at least 20 resolvable forecasts and calibration as questions resolve;
4. a verified net-worth and Zürich-ownership baseline;
5. continuing JM105 panel verdicts with saved scientific proof.

If those outputs do not exist, the agency is still observational regardless of how sophisticated its architecture appears.
